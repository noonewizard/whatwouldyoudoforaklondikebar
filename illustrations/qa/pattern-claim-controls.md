# DELIVERABLE 29 (VISUAL) — CONTROLS FOR PATTERN CLAIMS

The series investigates hidden messages, geometry, numerology, ciphers, and
symbolic relationships. Its illustrations must therefore **teach the reader how
pattern recognition misleads** — not merely report conclusions.

Four figure types carry this. They recur across Books II, III, IV, and V, always
in the same visual form, so the reader learns to read them.

## Type 1 — POSITIVE EXAMPLE

A pre-specified rule producing the expected output.

> Layout: input → rule → output, left to right, single row.
> Footer: **target fixed in advance: YES**.

## Type 2 — NEGATIVE EXAMPLE

The same process producing meaningless output.

> Layout: identical to Type 1, same scale, same position on the page.
> **The visual identity is the point** — the reader sees that the procedure
> looks the same and the result does not.

## Type 3 — MULTIPLE-TESTING EXAMPLE

A large transformation space generating apparent patterns by chance.

> Layout: a grid of the full search space, with hits marked.
> Footer: **n attempted**, hits found, expected by chance.
> The visual argument is **density**: the marked cells are numerous, and the
> reader sees that finding one was never unlikely.

## Type 4 — CONTROL COMPARISON

A control corpus producing similar patterns.

> Layout: **two panels in one frame, shared scale, side by side.**
> Left: target. Right: matched control with no claim attached.
> Footer: how the control was matched, and on what.

**Type 4 figures may never be split across a spread.** If the control is on
another page, the reader will not make the comparison, and the figure has failed.

## The standing rule

> **A figure showing a found pattern without its control reproduces the error the
> books diagnose.**

This is check 6 of the Visual Argument Audit, and it is blocking.
